The plumbing held. The detector failed its own gate.

official gate run · 2026-07-09 · gate-9328e564 gate committed 2026-07-07, before the run repo verified @ 62f5935 RESULT: FAIL, PUBLISHED AS IS

Bounded AI agents check iGaming operator and affiliate pages against three synthetic rule sets, inside a deterministic control plane with a human approval gate; on the official run, scored on synthetic data, the orchestration leg of the gate passed and violation detection failed its precision gate, 0.844 against 0.95.

The problem

iGaming content, on operator and affiliate sites alike, is published under several regulatory regimes at once (MGA, UKGC and German GlüStV-style themes). Content that is compliant in one jurisdiction can break the rules of another, rules change, and manual review does not scale. A single unbounded agent "checking compliance" cannot be trusted or audited. A finding is only useful if it traces to a specific rule and a specific piece of evidence.

The rule sets here are synthetic: modelled on publicly known regulatory themes, not copied from real regulatory text, and not reviewed by counsel. The system demonstrates the orchestration pattern. It makes no claim of legal accuracy.

What was built, and the gate committed first

One checker agent per jurisdiction reads a page against its own rule set only. A second agent, the already published ai-claim-verification-agent, reused unmodified and pinned to one commit, re-checks each violation a checker reports and returns CONFIRMED, REJECTED or DISPUTED. A planner agent drafts a fix for confirmed violations only, and a human approves or rejects each fix in a command-line tool. Everything between the agents (task state, severity ranking, schema checks, dead-letter routing) is deterministic Python. No model decides what runs next.

The pass and fail bar lives in evals/eval_config.yaml. Any leg that fails, fails the gate.

Where it failed

On the synthetic eval set, all 8 misses (5 false positives, 3 false negatives) came from the checker, in GBR and MLT; DEU scored clean. The adjudicator confirmed all 32 violations it was given and rejected none, so on this run it added no precision protection. The record says so instead of giving it credit. What this run proves, and what it does not

It proves the control plane held under one full official run on the synthetic eval set: 23 of 23 check tasks, 17 of 17 verify tasks and 32 of 32 plan tasks reached a terminal state, with zero lost and zero dead-lettered, and failure-injection tests FI-1 to FI-7 were green. A bounds check of the audit log found no reference to the answer-key file in any agent tool payload for the run.

It does not prove the detector is accurate enough: it failed its precision gate. It does not prove legal accuracy, because the rules are synthetic. It does not prove the adjudicator adds precision, because on this run it rejected nothing. And the idempotent re-run is shown by a unit test, not by repeating this run.

KNOWN LIMITATIONS, SELF-DECLARED

  • Rules are synthetic, modelled on public regulatory themes. The system demonstrates the governance pattern, not legal coverage.
  • The answer key was split across actors (spec and key: Claude; pages: Claude Code; blind labels: ChatGPT; adjudication: Kristian), which removes key-authorship leakage. The page author still knows what it planted, and pages, key and checkers share a model family.
  • Checker and verifier share a model. Adjudication guards against per-finding error, not model-family blind spots.
  • Counts per jurisdiction are small (MLT 7, GBR 13, DEU 10 violations). At recall ≥ 0.90, MLT tolerates zero misses before failing; GBR and DEU tolerate one each.

The decision on record

ADR 0001: DETERMINISTIC CONTROL PLANE · ACCEPTED 2026-07-07

The orchestrator (task ledger, state machine, schema checks, dead-letter routing, resume from the ledger, severity ranking) is deterministic Python, and no model call starts in the control plane. Agents analyse and recommend; they never decide what runs next, a payload's severity, or whether a task is done. The trade-off is recorded: the system cannot adapt its routing to what an agent says. The build proves orchestration discipline, not routing intelligence.

On 2026-07-09 Kristian decided to publish the FAIL as the final v1.0 result, with no re-run in that cycle. One step stays open on the record: an optional remediation pass, capped at one re-gate, and a second FAIL after it would also be published.
