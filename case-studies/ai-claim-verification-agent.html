It scored 35 of 35 while eight of its test folder names contained a verdict word.

gate run · 2026-07-06 · eval-05fbe4ee neutral-name re-run · 2026-10-13 · eval-199f77c6 repo verified @ bd6184e RESULT: GATE PASS ON BOTH RUNS · PRECISION 1.00 · RECALL 1.00

An agent that checks the factual claims on pages such as affiliate reviews and product pages against their sources, with four read-only tools and nothing else, passed its precision and recall gate on 12 synthetic cases with all 35 claims correct, before and after verdict words were removed from eight test folder names.

The problem

Affiliate reviews, comparisons and product pages make factual claims (prices, specs, availability, release dates) that should match their sources but often go unchecked. Checking by hand is slow, and it is the first thing skipped when a deadline is close.

An AI agent could do the checking, but the README names the catch: an agent that can act freely near live content is a liability, because one bad decision can publish, edit or send something it should not. The README's answer is an agent that investigates on its own and can do nothing else.

What was built, and the test it was held to

The agent takes one target page and its source pages, extracts the target's claims, investigates each one against the sources, and logs one verdict per claim: SUPPORTED, CONTRADICTED or UNVERIFIABLE, with the evidence source. It is built on the Claude Agent SDK, and the bounds sit in the harness code, not in the prompt: the only tools the model can call are four custom ones (fetch_page, extract_claims, compare_source, log_finding), every built-in tool is switched off, a run stops at 20 turns, the SDK enforces a per-run cost ceiling, and a separate counter in the tool code stops a run after 60 tool calls. Hooks before and after every tool call write it to a local SQLite audit log. The page tools only read local HTML under the dataset folder and reject any path outside it. No tool decides a verdict; the model reads the source text and decides.

The gate was committed before the agent existed. The thresholds (precision at least 0.95 and recall at least 0.90) were committed on 2026-07-05 (b041702); the 12 synthetic cases and their answer key (767352b), then the metric definition and the comparison policy (2205665), followed early on 2026-07-06; the agent code came after them (a420efb), then the eval runner (6175a6f), then the official run (bc9f41a). The positive class is CONTRADICTED: precision asks how many of the claims the agent called contradicted really were, recall how many of the 8 truly contradicted claims it caught. Overall accuracy across all 35 claims is reported, not gated, and a claim left without a verdict is scored wrong. The policy the agent is prompted with is the same file the answer key follows: numbers must match exactly, a rephrased fact counts as the same fact, manufacturer and retailer sources outrank forum posts, and a claim no source mentions is UNVERIFIABLE, not CONTRADICTED. Three cases are built as traps: a near-match number (sources say 11.5 hours, the page says 12), a price spelled out in words, and a forum post that repeats the page's figure against the manufacturer's spec sheet.

The run

The official gate run, eval-05fbe4ee, ran on 2026-07-06 with Claude Sonnet 4.6, one fresh agent invocation per case. Every one of the 35 verdicts matched the answer key. No case hit the turn cap or the cost ceiling; cases took 7 to 11 turns, and the run cost $0.9047 in total, against a ceiling of $1.50 per case. An earlier shakedown run on Claude Haiku 4.5 gave the same verdicts.

What the record shows was wrong

The first attempt at the gate run crashed. The cost ceiling, $0.25 per case, had been set for the cheap Haiku development runs; the first Sonnet attempt hit it in the middle of a turn on case 1, and the SDK raised a hard error instead of returning a capped result. The results file records it as a real gap in the harness, caught by the run crashing and not by the eval runner. The fix: the runner catches that error and scores the case's claims as unresolved, which counts as wrong, and eval runs got their own ceiling of $1.50 per case.

The larger problem was in the test folder names. Until 2026-10-13, 8 of the 12 case folder names contained a verdict word, and the folder name reached the model in the target and source paths of the prompt; the fetch_page tool description also carried one of the old names, case_01_supported_wireless_earbuds, as a fixed example path. In six of the eight, the name also carried the topic of the claim with that verdict. Since 2026-09-22 (664ea27) the portfolio site's card for this agent had said its evaluation was confounded by the folder names and did not present its scores as blind accuracy evidence.

What this proves, and what it does not

It proves that on 12 hand-written cases the agent passes a gate fixed before it was built, with every verdict correct, and still does when the folder names no longer carry verdict words. It does not show whether the model used those words in July; it shows that the agent, with the same scorer, thresholds and model, scores the same without them. One bound is tested in CI: a 25-test suite, which CI runs on Ubuntu, macOS and Windows with Python 3.12 and 3.14 on every push and pull request to main, checks that paths outside the dataset folder, including escape attempts, are rejected. Two of the 25 tests read a local audit log, which is not committed, so they skip in CI and a reader cannot re-run them: one checks that every path the pinned eval run touched stayed inside the dataset folder, the other that the answer file's name and claim IDs never reached the model. The tool list, the turn cap, the cost ceiling and the call counter are set in code and not tested.

It does not prove the agent works on real web pages: the cases are clean local HTML, with none of the ads, nested markup or script-rendered content of real pages. It is not a tight estimate either: with 8 contradicted claims, one miss would put recall at 0.875, below the 0.90 gate (the results file calls 0.875 "comfortably above" the gate; it is not). And the trap cases were written by the same person who wrote the comparison policy the agent is prompted with, so the eval and the prompt may be tuned to each other; renaming the folders does not change that.

KNOWN LIMITATIONS, SELF-DECLARED

  • All 12 cases are synthetic, hand-written local HTML, chosen for exact ground truth; the eval cannot yet speak to real-world page noise.
  • 12 cases and 35 claims catch gross failures and test the three trap patterns; they do not give a statistically tight precision or recall.
  • Claim types not represented are untested: ranges, conditional claims, claims spread over several paragraphs, and partial disagreement across three or more sources.
  • The agent cannot fix what it finds; a verdict needs a person to act on it.
  • The Agent SDK and its CLI are not version-pinned, and runs do not record the versions they used.

The decision on record

ADR 0001: BOUNDED AGENT V2, READ-ONLY WHITELIST, AND WHY THIS REPO IS FULLY PUBLIC · DATED 2026-07-05 · ACCEPTED 2026-07-06 ON THE FIRST AGENT COMMIT

The earlier engines in the portfolio follow a rule in which deterministic code acts and the AI only recommends. An agent breaks that frame: the model must choose its own next step, or it is just a pipeline. So the risk to bound is not that the AI decides, but that it decides something irreversible. The rule here: the model may choose the next read-only investigative action from a fixed whitelist of four tools, within hard limits on steps and cost, and may never publish, edit, send or make an irreversible change, with the bounds enforced in the harness. The record also makes this repository fully public, prompts included, because for an agent the prompts and bounds are the work. The trade-offs are written down: the agent cannot fix what it finds, and public prompts can be copied.

The next step the repository records as open is demo assets, a recording or GIF: its second decision record, on the demo script, puts them in scope, and they are not shipped until they exist.
